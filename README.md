# HW56 · Loop Lab

Реализация исходного nodejs-hw03-tests: process.nextTick, setImmediate, setTimeout(0), логирование и callback для каждой операции.

Функция возвращает Promise завершения всех трёх операций. Синхронные сообщения выводятся до callback. Callback получает nextTick, setImmediate и setTimeout; после каждого вызова выводится сообщение о завершении. Синхронное исключение callback отклоняет Promise и предотвращает последующие callback. Callback должен быть обычной синхронной функцией; ожидание его собственного асинхронного результата в контракт не входит.

## Важная оговорка о порядке

Приложенный тест требует точного порядка nextTick → setImmediate → setTimeout. Чтобы гарантировать его и с реальными таймерами, setTimeout создаётся внутри callback setImmediate. Это осознанно заданная последовательность, а не универсальное правило Node.js: у независимых setImmediate и setTimeout(0) порядок зависит от контекста. Таким образом требование теста выполнено без закрепления неверного обобщения из упрощённой формулировки задания.

Импорт src/main.js ничего не запускает: демонстрация вынесена в scripts/demo.mjs. Исходный тест не изменён. Vitest использует environment=node, pool=threads и явно мокирует nextTick; с pool=forks такой мок не поддерживается. Дополнительные нативные тесты проверяют настоящий Event Loop, а не только fake timers.

## Запуск Node.js

Рекомендуемая среда проекта — Node.js 24. Для этих команд установка пакетов не требуется:

```bash
npm start
npm run test:logic
```

Исходные тесты задания требуют Vitest:

```bash
npm install
npm test
npm run check
```

Используйте npm. Старый yarn.lock из шаблона не используется и не копируется утилитой prepare-repositories.mjs в готовый репозиторий. После npm install сохраните новый package-lock.json. Команда npm ci применима только после его появления. Среда Vitest заменена с браузерной jsdom на node, глобальные console/fetch больше не подменяются бесконтрольно.

## Страница в браузере

```bash
npm run dev
```

Откройте http://127.0.0.1:4173/. Сборка и просмотр также не требуют установки пакетов: используются встроенные модули Node.js.

```bash
npm run build
npm run preview -- --port 4174
```

Встроенный сервер привязан к 127.0.0.1 и предназначен только для локального просмотра. Для проверки пути репозитория:

```bash
npm run preview -- --port 4174 --base /repository-check/
```

Адрес: http://127.0.0.1:4174/repository-check/. Остановка — Ctrl+C.

## Что публикуется на Pages

При сборке реально исполняется src/main.js через scripts/demo-data.mjs. Консоль и результаты записываются в dist/demo.json вместе с версией Node и временем запуска. Страница показывает эту запись, а не притворяется сервером. Браузерная песочница отдельно подписана: Web API в 54, память страницы в 55, воспроизведение записи в 56.

Workflow сначала выполняет нативные и исходные Vitest-тесты, затем сборку и публикацию. Демо после создания репозитория: https://USERNAME.github.io/REPOSITORY/ — замените шаблон после успешного deploy. Инструкция: [docs/PUBLISHING.md](docs/PUBLISHING.md).
